# Code Generation

Ormed uses source generation to produce strongly-typed models and metadata.
This page owns the generator workflow: the tooling, generated files, builder
configuration, and verification steps.

Code generation is optional. If you only need raw SQL, schema operations, or
ad-hoc table queries, use [Direct Database Access](./direct-database) instead.

## Add Generator Tooling

The generator runs through `build_runner`. Add it to `dev_dependencies`:

```yaml
dev_dependencies:
  build_runner: ^2.10.4
```

If you are following [Quick Start](./quick-start), you will also use
`ormed_cli` for project scaffolding, migrations, and seeders. Add it locally
for a version-pinned workflow, or follow [CLI Overview](../cli/overview) for
the global option:

```yaml
dev_dependencies:
  ormed_cli: ^0.3.0
```

Resolve the tooling before running a build:

```bash
dart pub get
```

## Running the Generator

Add the builder and run:

```bash
dart run build_runner build --delete-conflicting-outputs
```

Or use watch mode for development:

```bash
dart run build_runner watch --delete-conflicting-outputs
```

Use `build` in CI and one-off runs. Use `watch` during active model iteration.

## Generated Files

The generator produces several files:

| File | Description |
|------|-------------|
| `<model>.orm.dart` | Model definition, codec, factory, and relation getters |
| `<model>.orm_model.json` | Intermediate metadata for auto-registry (can be gitignored) |
| `lib/src/database/orm_registry.g.dart` | Auto-generated registry of all ORM models |

### Per-Model Generated Code

For each `@OrmModel` class, the generator creates:

- **`$ModelName`** - Tracked model class with change tracking
- **`ModelNameOrmDefinition`** - Model metadata and static helpers
- **`$ModelNamePartial`** - Partial entity for projections
- **`ModelNameInsertDto` / `ModelNameUpdateDto`** - Data transfer objects
- **`ModelNameModelFactory`** - Factory helpers for test data (if `ModelFactoryCapable` is used)

## Builder Configuration

Configure the builders via `build.yaml`:

### Model Generator (`ormed`)

Generates `.orm.dart` files for each annotated model:

```yaml
targets:
  $default:
    builders:
      ormed|ormed:
        enabled: true
        generate_for:
          - lib/models/**
```

### Auto-Registry Builder (`orm_registry`)

Aggregates all models into a single registry file:

```yaml
targets:
  $default:
    builders:
      ormed|orm_registry:
        enabled: true
        options:
          output: lib/src/database/orm_registry.g.dart  # default
```

### Custom Output Location

```yaml
targets:
  $default:
    builders:
      ormed|orm_registry:
        options:
          output: lib/src/database/models.g.dart
```

### Disabling Auto-Registry

If you prefer manual registration:

```yaml
targets:
  $default:
    builders:
      ormed|orm_registry:
        enabled: false
```

Then register models manually:

```dart file=../../examples/lib/setup.dart#manual-registration
```


## Tips

- Keep model constructors `const` when possible
- Use `@OrmField(ignore: true)` for computed properties
- Re-run `build_runner` whenever annotations change
- Generated files are not meant to be edited manually

## Verify Generation

After running build:

1. `dart analyze` has no generation-related errors.
2. Your model directory includes fresh `*.orm.dart` files.
3. `lib/src/database/orm_registry.g.dart` includes your newly added models.
