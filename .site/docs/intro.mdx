# Introduction

Ormed is a **strongly-typed ORM for Dart** that stays useful before and after
code generation. Connect directly to a driver for raw SQL and ad-hoc tables,
then add generated models when your domain needs stronger contracts.

Before you start: Basic Dart familiarity.

## First 15 Minutes

If you want the shortest path to a running query, choose one of these lanes:

1. **Start with the database** — [Direct Database Access](/docs/getting-started/direct-database)
   connects without code generation.
2. **Start with your domain** — [Installation](/docs/getting-started/installation) and
   [Quick Start](/docs/getting-started/quick-start) scaffold generated models.

Both paths meet at [DataSource](/docs/queries/data-source), [Query Builder](/docs/queries/query-builder),
and the same driver adapters.

Use [Adopt Existing Project](/docs/getting-started/adopt-existing-project) instead of Quick Start if your app already has an established schema/runtime.

## Learning Path

Follow this order to go from first contact to fluent usage:

1. **Pick a starting lane**: [Direct Database Access](/docs/getting-started/direct-database) or
   [Installation](/docs/getting-started/installation) -> [Quick Start](/docs/getting-started/quick-start)
   Existing app path: [Adopt Existing Project](/docs/getting-started/adopt-existing-project)
2. **Understand runtime setup**: [Configuration](/docs/getting-started/configuration) -> [DataSource](/docs/queries/data-source)
   -> [Code Generation](/docs/getting-started/code-generation)
3. **Model your domain**: [Models Overview](/docs/models/overview) -> [Relationships](/docs/models/relationships)
4. **Query and mutate data**: [Queries Overview](/docs/queries/overview) -> [Repository](/docs/queries/repository)
5. **Evolve schema safely**: [Migrations Overview](/docs/migrations/overview) -> [Running Migrations](/docs/migrations/running-migrations)
6. **Choose deployment driver**: [Drivers Overview](/docs/drivers/overview) -> driver-specific pages
7. **Operational fluency**: [Guides Overview](/docs/guides/overview), then [Testing](/docs/guides/testing) + [Observability](/docs/guides/observability)

## Features

- **Type-safe queries** - Fluent query builder with compile-time type checking
- **Code generation when you want it** - Automatic generation of model definitions, codecs, and helpers
- **Driver-first boot** - Connect, migrate, query, and run raw SQL without generated code
- **Flexible input handling** - Accept tracked models, DTOs, or raw maps for CRUD operations
- **Relationship support** - hasOne, hasMany, belongsTo, belongsToMany with eager/lazy loading
- **Soft deletes** - Built-in support for soft delete patterns
- **Timestamps** - Automatic timestamp management for created_at/updated_at
- **Migrations** - Fluent schema builder with reversible migrations
- **Multi-database** - Support for SQLite, PostgreSQL, MySQL, and D1
- **Drift integration** - Share a Drift executor with Ormed queries and reactive watchers
- **Value codecs** - Custom type serialization between Dart and database
- **Observability** - Ordered query interceptors and a built-in Dartastic OpenTelemetry adapter

## Installation

Add Ormed to your `pubspec.yaml`:

<Tabs groupId="intro-install" defaultValue="pubspec">
<TabItem value="pubspec" label="pubspec.yaml">

```yaml
dependencies:
  ormed: ^0.3.0
  ormed_sqlite: ^0.4.0
```

</TabItem>
<TabItem value="commands" label="Commands">

Then run:

```bash
dart pub get
```

Choose [Direct Database Access](/docs/getting-started/direct-database) if you
do not need generated models yet. For generated models, add the tooling from
[Code Generation](/docs/getting-started/code-generation) before continuing to
[Quick Start Guide](/docs/getting-started/quick-start).

</TabItem>
</Tabs>
